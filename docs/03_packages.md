# 03. パッケージ管理（Pkg）

所要の目安: **約10分**（Julia 入門の一部）

Julia のライブラリは **パッケージ** として配布されます。日常的に使う操作は次のとおりです。

---

## 1. Pkg モードに入る

REPL で **`]`**（右角括弧）を押すと、プロンプトが `pkg>` になります。

戻る: **Backspace**（または `Ctrl + C`）

---

## 2. よく使うコマンド

| コマンド | 意味 |
|----------|------|
| `add CSV` | パッケージを追加（現在の環境へ） |
| `rm CSV` | パッケージを削除 |
| `status`（短く `st`） | 入っているパッケージ一覧 |
| `update` | 互換範囲内で更新 |
| `activate .` | **このフォルダ** をプロジェクト環境にする |
| `instantiate` | `Project.toml` に書かれた依存をインストール |

この教材リポジトリでは、すでに `Project.toml` に **CSV, DataFrames, Plots, Statistics**（Statistics は標準ライブラリですが、Julia の新しいバージョンでは明示的に依存へ書くことがあります）が書かれています。初回は:

```
] activate .
] instantiate
```

だけで足ります。

---

## 3. グローバル環境に入れすぎない理由

`pkg>` で `activate` せずに `add` すると、**グローバル環境**（`@v1.x`）にパッケージが溜まります。

- プロジェクト A と B で **別バージョン** が必要なときに衝突しやすい
- 再現性のある共有（GitHub 上の `Project.toml`）とズレやすい

**習慣**: リポジトリのルートで `] activate .` してから作業する。

---

## 4. `Project.toml` と `Manifest.toml`

| ファイル | 役割 |
|----------|------|
| **Project.toml** | プロジェクト名・依存パッケージ・**互換バージョン（`[compat]`）** など。**Git にコミットする** |
| **Manifest.toml** | その時点で実際に解決された **全パッケージの正確なバージョン** のロックファイル |

`instantiate` は `Project.toml`（と、あれば `Manifest.toml`）を読んで環境を再現します。

---

## 5. このリポジトリで `Manifest.toml` をコミットしない方針

`.gitignore` で `Manifest.toml` を除外しています。理由の要点:

1. **OS や Julia のマイナーバージョン** によって Manifest の中身が変わりやすく、全員で同じファイルを維持しづらい  
2. 代わりに `[compat]` で「この範囲なら動く」と示し、**各人の環境で `instantiate` 時に合うバージョン** が選ばれる  
3. ゼミ入門では「全員が同じ分析をおおむね再現できればよい」ことが多い

### コラム: 論文用の厳密な再現性

論文やレポートの **最終分析** では、将来の自分や査読者のために **`Manifest.toml` もコミットする** のが一般的です。そうすると数年後でも **ピンポイントのバージョン集合** を復元できます。

- **教室・ハンズオン**: Manifest なし + `compat`（今回）  
- **研究の本番リポジトリ**: Manifest あり、がよくある使い分けです

---

## 6. 確認クイズ（自分用）

1. 今の環境を確認する `pkg>` コマンドは？ → `status`  
2. チームメンバーが clone したあと最初に打つべきは？ → `activate .` と `instantiate`  
3. 新しいパッケージを **この教材に** 追加したいときは？ → `add パッケージ名`（`Project.toml` が更新される）
