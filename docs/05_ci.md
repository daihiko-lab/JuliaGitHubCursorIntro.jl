---

## 1. CI とは

**CI（Continuous Integration）** は、コードを GitHub に送るたびに、決まったチェック（テストやフォーマット確認など）を **自動で実行** する仕組みです。

このリポジトリでは **GitHub Actions** を使い、設定ファイルは次にあります。

- [`.github/workflows/CI.yml`](../.github/workflows/CI.yml)

---

## 2. いつ動くか

- **`main` への push**
- **Pull Request** の作成・更新（新しい commit を push したとき）

PR 課題を出すと、数分以内にチェックが始まるのが普通です。

---

## 3. PR 画面での見方

1. GitHub で自分の PR を開く
2. ページ下部付近の **Checks**（またはコミット横の **✓ / ✗**）を見る
3. すべて **緑（pass）** なら合格ライン  
4. **赤（fail）** のときは、失敗したジョブ名をクリックして **ログ（Log）** を開く

### ログの読み方のコツ

- **下にスクロール** すると、エラーメッセージの塊が出ることが多い
- `ERROR:` や `Test Failed` などを探す
- ローカルで再現: リポジトリルートで

  ```bash
  julia --project=. -e 'using Pkg; Pkg.test()'
  ```

  と同じテストが走ります（事前に `instantiate` 済みであること）。

---

## 4. このリポジトリの CI でやっていること（概要）

| 内容 | 説明 |
|------|------|
| **テスト** | `test/runtests.jl`（例: `submissions/*.jl` が実行できるか） |
| **複数 OS** | Ubuntu に加え、Mac / Windows でも `release` 系 Julia でテスト |
| **Runic** | Ubuntu の `release` ジョブで、Julia コードのフォーマットチェック |

詳細はワークフローファイルを見てください（当日はオーナーが画面共有する想定です）。

---

## 5. 落ちたときに参加者が確認すること

1. ローカルで `] instantiate` 後、`Pkg.test()` または `julia test/runtests.jl` 相当が通るか
2. `submissions/ユーザー名.jl` にタイポや構文エラーがないか
3. 直したら **もう一度 commit → push** すると、同じ PR 上で CI が再実行される
